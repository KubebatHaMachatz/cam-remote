# cam-remote — סקירה קצרה

## מה זה

אפליקציית אנדרואיד ללא ממשק משתמש, שמאזינה לפקודות ברשת המקומית, ואפליקציית שליטה ב-Python שמריצה
אותן ממחשב אחר. שלוש היכולות שהמטלה ביקשה:

| היכולת | הפקודה |
|---|---|
| פתיחת אפליקציית המצלמה | `open-camera` |
| צילום במצלמה האחורית ושמירת התמונה | `take-picture` |
| קריאת מאפיין מהמכשיר | `getprop` |

בנוסף `status`, `commands` ו-`camera-apps` — כלי אבחון, לא יכולות ליבה. האבחנה הזו מוצהרת על ידי
הסוכן עצמו, ולכן `camremote commands` מציג שתי רשימות נפרדות.

## איך מריצים

```bash
cd android && ./gradlew assembleDebug          # מתקינים את ה-APK ופותחים את האפליקציה פעם אחת
./scripts/camremote --host 10.0.0.4 status     # הכתובת מופיעה בהתראה שעל המכשיר
```

פירוט מלא: [QUICK-START.md](QUICK-START.md) — עמוד וחצי.

## ארכיטקטורה

**Ports & Adapters (הקסגונלי)**, בשני מודולים:

- **`:core`** — Kotlin/JVM טהור, בלי אנדרואיד ב-classpath. כאן נמצאות כל ההחלטות: אילו פקודות
  קיימות, מה מותר, אילו שגיאות מוחזרות.
- **`:app`** — כל מה שאנדרואידי: המתאמים (CameraX, MediaStore, Intent), שרת ה-HTTP והשירות.

הכלל "לליבה אין תלות באנדרואיד" נאכף על ידי המהדר ולא על ידי משמעת — זו הסיבה שהפיצול לשני מודולים
קיים. התוצאה המעשית: כמעט כל הלוגיקה נבדקת ב-JVM רגיל תוך שנייה, בלי מכשיר ובלי אמולטור.

**Command + Registry**: הוספת פקודה חדשה נוגעת בשני קבצים — מחלקה חדשה ושורה אחת ב-`AppContainer`.
בלי נתיב HTTP חדש, בלי שינוי פרוטוקול, ובלי לעדכן את הלקוח: `system.commands` מחזיר את הקטלוג
מהמכשיר, כך שלקוח קיים מציג פקודה שמעולם לא הודר מולה.

MVVM/MVC לא רלוונטיים כאן — הם דפוסי הצגה, ולאפליקציה אין מסך. מה שיש כאן הוא שרת: בקשה נכנסת,
נשלחת לביצוע, תשובה יוצאת.

## החלטות שכדאי לשים לב אליהן

- **בלי adb במוצר.** התקשורת היא רשת בלבד. זה גם התברר כהכרחי: מכשיר ה-ColorOS שעליו פותח הפרויקט
  חוסם `pm grant` לגמרי.
- **בלי הרשאת אחסון.** התמונות נשמרות ב-`Documents/cam-remote/` דרך MediaStore. תחת scoped storage
  אפליקציה רשאית ליצור קבצים משלה בכל מקום באחסון המשותף בלי הרשאה כלשהי — ולכן `minSdk` הוא 29,
  כדי שהכלל יתקיים תמיד. ההרשאה היחידה שהצילום דורש היא `CAMERA`.
- **מסך אחד שלא מצייר כלום.** אנדרואיד לא מאפשר לשירות רקע לבקש הרשאה בלי Activity, ולכן קיימת
  `LaunchActivity` שקופה לחלוטין. המשתמש רואה רק את הדיאלוגים של המערכת.
- **בלי אימות.** ההנחה היא סוכן אחד ולקוח אחד ברשת אמינה — זו המסגרת של המטלה. החשיפה מתועדת
  במפורש ב-[DESIGN.md](DESIGN.md) §7, וב-[EXTENDING.md](EXTENDING.md) יש דוגמה מלאה להוספת אימות.
- **גילוי אוטומטי (mDNS) הוסר.** הוא מומש ועבד, אבל ה-Galaxy S24 פשוט לא עונה לשאילתות אחרי
  הרישום הראשוני — 123 מנות mDNS בחמש-עשרה שניות, אף אחת מהמכשיר. כתובת שנמצאת לפעמים גרועה
  מכתובת שתמיד מקלידים, במיוחד כשההתראה על המכשיר מציגה אותה ומעדכנת את עצמה כשהיא משתנה.
  המדידות ב-[DEVICES.md](DEVICES.md).

## בדיקות ותהליך

פותח ב-TDD: בדיקה נכשלת, ואז המימוש. ההיסטוריה ב-git משקפת את זה — commits מסוג `test:` ו-`feat:`
בזוגות.

| חבילה | כמות | רצה על |
|---|---|---|
| `:core` | 177 | JVM שולחני, בלי אנדרואיד |
| `:app` | 10 | JVM שולחני — מסלולי ה-HTTP |
| Python | 56 | ספרייה סטנדרטית בלבד |
| Instrumented | 7 | מכשיר אמיתי: חיישן, MediaStore, סוקט |

שלושה דברים ש-TDD לא יכול לכסות, ולכן נבדקו ידנית על חומרה: שחיישן אמיתי מייצר JPEG אמיתי, שמערכת
ההפעלה מרשה הפעלת Activity מהרקע, ושהסוכן נגיש ברשת פיזית. הכול אומת על שני מכשירים —
realme RMX3563 ו-Samsung Galaxy S24, שניהם Android 14 — ועל אמולטור API 37.
